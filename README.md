# A Manifesto for a Trusted AI Agent

> This is a constitution for an AI agent. Not a framework to sell — a foundation to trust.

---

## What This Is

This repository is inspired by [OpenClaw](https://github.com/openclaw/openclaw) but is **personalized for [@infiloop2](https://github.com/infiloop2)** and designed to be an AI agent you can actually trust.

It provides:
- **Clear constraints** on what the agent can and cannot do
- **Explicit controls** over agent behavior and data access
- **Full articulation** of everything you need to trust for those controls to hold

This is personalized and optimized for how infiloop2 thinks about trust and control.

### Why Open Source?

Not to build a community or grow adoption. The reason is **scrutiny**.

More eyes on the code means more confidence in its integrity. If other humans connect with this philosophy, they're welcome to contribute — but that's a side effect, not the goal.

## Trust Model

Before you proceed, understand exactly what you're trusting.

### Rule #1: Understand and Verify

As you proceed with the setup, you will add trust assumptions on code libraries and infrastructure providers.

**Just remember Rule #1: understand and verify the whole repo code before you fully start trusting it.**

### 1. Verify This Repository

Don't trust — verify. Trust only your brain's comprehension of every word and line of code in this repository.

If you can't or won't verify it yourself, you can delegate this trust to another human who verifies it for you. But understand: you're then trusting that person, not the code directly.

Full effort is made to keep the implementation **as simple as possible** to make verification achievable. Simplicity is not a nice-to-have; it is a core design principle.

> ⚠️ **The code is the law.**  
> Natural language explanations (including this README) could mislead you, intentionally or not.  
> When in doubt, read the code. The code is the source of truth.

### 2. Trust Dependencies (As You Grow)

As you proceed with setup, you will use certain dependency code and infrastructure. Each dependency becomes a new trust assumption.

These will be explicitly called out as you encounter them. Start with just assumption #1 above, then proceed to setup.
